WHAT IS VIBE CODING

วงจรเดียวที่ต้องจำ

บอกเขียนสิ่งที่อยากได้ ให้ชัด
→
ให้ AI ลงมือagent เขียนโค้ดแทนคุณ
→
ตรวจเทียบกับสิ่งที่ขอไว้

งานของ PM ในวงจรนี้ คือ ขั้นแรก กับ ขั้นสุดท้าย — ไม่ใช่ตัวกลาง
นั่นคือเหตุผลที่ PM เรียนอะไรนี้ได้เร็วกว่า dev หลายคน

กฎข้อเดียวของวันนี้

"The card is the contract."
การ์ดที่คุณเขียน คือสัญญา — AI ต้องทำตาม
และคุณต้องตรวจรับเหมือน UAT ทุกครั้ง

ถ้าการ์ดกำกวม → AI เดา → ผลลัพธ์พัง แล้วคุณโทษ AI
ถ้าการ์ดชัด → ผลลัพธ์คือของจริง

CH1 · 0:25 – 1:05

เขียนการ์ดแบบที่ dev เขาเรียกว่า "ใช้ได้"

โครงการ์ด (English template)

  • User story — As a <who>, I want <what>, so that <why>
  • Acceptance criteria — 3 ข้อ เช็คได้ สังเกตได้
  • Out of scope — วันนี้ยังไม่ทำอะไร

เกมทดสอบ: Grilling

  • จับคู่ โจมตีการ์ดของกันและกัน
  • ถ้า dev ต้องถามกลับ = การ์ดยังไม่เสร็จ
  • เป้าหมายวันนี้: การ์ด 2 ใบ ใน repo จริง
CH2 · 1:05 – 1:50

จากการ์ด → โปรแกรม ด้วย Spec Kit

ทีมจริงใน industry เขาทำ spec-driven development — วันนี้คุณได้ลองแบบที่ dev เขาทำกันจริง

$ speckit-tasks  # แผนงานแยกเป็น step ที่เช็คได้
$ speckit-implement  # ให้ agent ลงมือทำทีละ step

สิ่งที่คุณทำ: ดู agent ทำ → เทียบกับ 3 acceptance criteria ในการ์ด
ไม่ตรง = ไม่รับ ส่งกลับเข้าการ์ด ไม่ใช่แกะโค้ดเอง

ทักษะที่เอากลับไปใช้จริง

Correction loop — เมื่อ AI ทำผิด

01ระบุว่า อะไร ไม่ตรงกับ ข้อไหน ในการ์ด (ไม่ใช่ "มันพัง")
02สั่งกลับด้วยข้อความที่อ้าง acceptance criteria ข้อนั้น
03ตรวจใหม่ — loop นี้คืองานประจำวันของ PM ยุคใหม่

เชื่อไหมว่ามาถึงตรงนี้ คุณกำลังทำสิ่งเดียวกับที่ทำกับ dev ในทีมอยู่แล้ว — แค่ dev คนนี้ตอบเร็วกว่า

CH5 · 3:25 – 4:00

แผนที่ workflow — มองให้เห็นทั้งภาพ
