Lesson 5 — แผนที่ workflow

4 ชั้น ไม่มีชั้นไหนแทนชั้นอื่นได้ — ไม่มีเครื่องมือไหนคือกระบวนการทั้งหมด

4 ชั้น

  1. Planning — การ์ดชัด = requirement ที่ agent เข้าใจ
  2. Spec Kit — เครื่องมือแปลงการ์ดเป็นงานที่เช็คได้ (องค์ประกอบ ไม่ใช่ SDLC ทั้งระบบ)
  3. Tests — เขียว = ผ่านเฉพาะจุดที่ cover ไม่ได้แปลว่าถูกทุกกรณี
  4. Browser QA — เขียวทั้ง suite ยังพังได้บนหน้าจอ

อย่า delegate (ยัง)

  • ข้อมูลลูกค้าจริง / PII — demo ใช้ข้อมูลปลอมเสมอ
  • ระบบเงิน การชำระเงิน compliance security
  • การตัดสินใจที่ย้อนกลับยาก

3 คำถามก่อนสั่ง agent ทุกครั้ง

  1. การ์ดชัดพอไหม จน "dev คนใหม่" ไม่ต้องถามกลับ?
  2. จะตรวจรับด้วยอะไร — และเมื่อไร?
  3. ถ้าพัง ย้อนกลับยังไง?

การ์ดแรกของวันจันทร์

เลือกงานจริงที่ เล็กพอเสร็จใน 1 ชั่วโมง แต่เจ็บพอที่จะอยากให้หายไป — เขียนการ์ดด้วย template เดิม แล้ว execute สัปดาห์หน้า โพสต์ผลใน community เป็น receipt
